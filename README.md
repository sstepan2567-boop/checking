# SystemDLC: восстановление исходников и проверка отдельных функций

Это проект анализа предоставленного `systemdc.zip`, а не готовая пересобираемая
версия клиента. Полученный C-псевдокод сохраняет адреса и ошибки декомпиляции;
исходные C++-классы, глобальные данные, имена переменных, структура сборки и полная семантика защиты
не восстановлены. Проверка запуска в Minecraft не выполнялась.

## Подтверждено

- `START.exe` вызывает `offline_loader_run` из `systemloader.offline.dll`.
- В секциях `.payload` обеих DLL находятся **плоские образы памяти**, а не
  обычные PE-файлы. Их нельзя корректно разобрать по старым `PointerToRawData`.
- Обёртки копируют образы целиком по фиксированным адресам и восстанавливают
  импорты. Клиент содержит 23 448 записей Windows unwind и 644 записи импортов;
  загрузчик — 2 763 и 350 соответственно. Это не количество игровых модулей:
  таблицы также включают библиотечный код и фрагменты функций.
- Клиент взаимодействует с JVM через JNI. Наличие секций `.themida` в старом
  заголовке не означает, что всё содержимое образа остаётся зашифрованным.
- Обёртка содержит локальное хранилище конфигураций и офлайн-ресурсы.

Подробнее: [доказательства и ограничения](docs/analysis.md).

Рабочий восстановленный компонент: `recovered/config/sdlc_key_decoder.py` —
декодирование переносимых конфигов `SDLC1` и проверка SHA-256. Это контрольная
сумма, не подпись и не лицензионный ключ. [Формат и операции](docs/configuration.md)
подтверждены статическим разбором; взаимодействие с запущенным клиентом не проверено.

```python
from recovered.config.sdlc_key_decoder import decode_key
configuration = decode_key(token)
```

Отдельный C++-фрагмент `recovered/native/jvm_attachment.cpp` восстанавливает
получение уже созданной JVM и подключение потока как daemon. Он компилируется
и тестируется с имитацией JVM; последующая инициализация клиента и TLS туда
не входят. Это реконструированный фрагмент, не исходная функция целиком.

## Содержимое готового архива

- `analysis/pseudocode/`: 25 129 успешных экспортов C-псевдокода клиента и
  3 704 — загрузчика. В `index.tsv` сохранены ошибки и thunk-переходы.
- `analysis/wrappers/`: декомпиляция START и двух внешних обёрток.
- `analysis/text/`: 60 698 строк с индексами и адресами, TSV и JSONL.
- `analysis/images/`: таблицы импортов/диапазонов и метаданные, **без бинарных образов**.
- `recovered/`: проверяемые реконструкции декодера конфигов, извлечения строк
  и фрагмента JNI; `tools/` и `tests/` — воспроизведение и проверки.

10 попыток декомпиляции завершились ошибкой; для 184 записей unwind автоанализ
не сохранил отдельную экспортируемую функцию. Это отражено в
[`evidence/coverage.json`](evidence/coverage.json); полнота восстановления не заявляется.
Генерируемые файлы включены в архив, но не в Git.

## Проверенные C++-компоненты

Добавлены валидаторы строк конфигурации и поиск по уже декодированному `TXT1`.
Поиск проверен по всем 60 698 ключам и 60 698 отсутствующим ключам: расхождений нет.
Это запуск нашей реконструкции над данными, **не исполнение машинного кода клиента**.
Подробности: [таблица строк](docs/text-table.md), [карта реестра модулей](docs/module-registry.md).

```sh
make all test
make verify-text ARCHIVE=/path/to/complete/systemdc.zip
```

`make all` собирает библиотеку компонентов, не готовый клиент.
Результат ранее выполненной ограниченной эмуляции валидаторов сохранён отдельно:
[границы и статус проверки](docs/dynamic-analysis.md). В текущем `STATIC_ONLY`
повторная эмуляция запрещена; `make dynamic` теперь проходит через guard навыка.

## Воспроизведение

Нужны Python 3, `uv`, `mise`, `curl`, `unzip`, `sha256sum` и `g++` для теста C++.
Скрипт установки использует фиксированные версии pefile, Ghidra и JDK;
исследуемые EXE/DLL не исполняются.

```sh
bash tools/setup_analysis.sh
export JAVA_HOME="$(mise where java@temurin-25.0.5+8.0.LTS)"
export GHIDRA_HOME="$PWD/.analysis-tools/ghidra_12.2_PUBLIC"
.analysis-tools/venv/bin/python tools/recover_images.py /path/to/systemdc.zip analysis/images
bash tools/analyze_image.sh loader
bash tools/analyze_image.sh client
.analysis-tools/venv/bin/python recovered/text/decode_text_table.py analysis/images/client/image.bin --out analysis/text
bash tools/test_native.sh
.analysis-tools/venv/bin/python -m unittest discover -s tests -v
```

Скрипт извлечения проверяет CRC ZIP и точные SHA-256 предоставленных DLL:
для другой сборки адресные константы применять нельзя. Выходные образы
предназначены только для анализа, не для исполнения или инъекции.

Результаты находятся в `analysis/images/`, `analysis/pseudocode/` и
`analysis/logs/`; большие производные файлы не добавляются в Git.
В `index.tsv` рядом с псевдокодом отмечены успешные, неудачные и пропущенные
попытки. `decompiled` означает, что Ghidra вернула текст, **не** доказанную
эквивалентность исходному машинному коду. Автоматические типы и границы функций
нуждаются в проверке; тайм-аут одной функции — 15 секунд.

## Безопасность и предел результата

Клиент, загрузчик и переносимые образы как программы не запускались; адреса
сервисов из образца не открывались. Ранее выполненная CPU-эмуляция двух валидаторов
не удовлетворяет строгому гейту изоляции приложенного навыка. После проверки
этого ограничения исполнение инструкций образца остановлено; текущая проверка
исполняет только авторскую реконструкцию и синтетические тестовые инструкции.
Сетевые импорты или найденные строки сами по себе не доказывают их использование.
Это не заключение об отсутствии вредоносного поведения.

Версия Minecraft **26.2 указана пользователем**. Совместимость с этой версией
не подтверждена запуском. Наличие JNI и нативного кода не исключает создания
Java-классов во время работы.
