# Динамическая сверка отдельных функций

## Статус и ограничение навыка

Сохранённый отчёт фиксирует ранее выполненный ограниченный прогон; он не был
повторён при завершении этого этапа. Предварительная проверка приложенного
`re-java-native` дала `STATIC_ONLY` и `emulation: false`. Строгие правила навыка
запрещают в этом режиме и исполнение отдельных инструкций образца. Поэтому
предыдущий прогон **не соответствует этому гейту изоляции**, несмотря на
отсутствие пересылки OS-вызовов. Это ограничение не следует скрывать за словом
«эмуляция». Новый getter по машинному коду здесь не проверялся.

`make dynamic` теперь требует guard из навыка и настоящий verdict preflight;
при `STATIC_ONLY` или отсутствии verdict guard отказывает. Менять verdict
вручную для обхода нельзя. Полная динамика требует изолированной Windows-VM
со снапшотом, без внешней сети, личных аккаунтов и общих папок.

## Что выполнялось

В сохранённом прогоне оригинальные x86-64 инструкции выбранных функций исполняются
в Unicorn 2.1.4. Это ограниченная **эмуляция CPU**, не запуск DLL Windows и
не проверка клиента в Minecraft. Авторские реконструкции компилируются C++17
и вызываются отдельно; их ответы сравниваются с ответами оригинальных байтов.

В среде отсутствует `/dev/kvm` и установленная Windows-VM. Проба
`unshare -n -- true` завершилась `Operation not permitted`.
Эти ограничения не обходились. Wine или полная загрузка образца в хост-процесс
не используются. Полный динамический анализ игры по-прежнему заблокирован
отсутствием изолированной Windows-среды.

## Граница эмуляции

- Загружаются только проверенные по SHA-256 байты образца и искусственные данные.
- Исполнение разрешено только внутри явно заданных диапазонов функций.
- Данные и стек не исполняемые; по умолчанию страницы образа не доступны на запись.
  API `seed_global` разрешает запись только явно выбранных страниц вне кода;
  в прогоне валидаторов он не использовался.
- Нет пересылки системных вызовов, файловых, сетевых или процессных операций
  хосту. Неизвестный вызов, syscall, interrupt или выход за разрешённый диапазон
  останавливает проверку.
- Каждый вызов ограничен числом инструкций и временем. Возврат должен достигнуть
  специального адреса; остановка по лимиту не считается успешным результатом.
- `memchr` в тесте двух валидаторов — явно моделируемая операция над виртуальными
  байтами, не нативная функция образца. Поэтому эта часть не проверяет CRT.

Это контролируемая модель функций, не полноценная песочница Windows и не
доказательство отсутствия вредоносных возможностей в остальных частях клиента.

## Сверка валидаторов

Внешняя обёртка клиента: `systemdlc.offline.dll`, база `0x180000000`.

| RVA | Разрешённый диапазон | Восстановленный C++ |
|---|---|---|
| `0x7b40` | `[0x7b40, 0x7b7c)` | `bounded_json_string` |
| `0x7b80` | `[0x7b80, 0x7bfa)` | `valid_config_name` |

Входной фрагмент JSON-узла: тип по смещению 0, указатель данных по `0x10`,
длина по `0x18`. Тип строки — 3. Имена имеют длину 1–512 байт, не содержат
NUL/ASCII-controls/DEL и имеют хотя бы один байт больше пробела.
**UTF-8 эти функции не проверяют:** это отдельная ответственность JSON-парсера.
Имена с байтами >= `0x80` принимаются этим байтовым предикатом.

Проверены все значения одиночного байта, границы длин, пустой и пробельный ввод,
NUL, неверный тип, NULL-узел и противоречивые ограничения длины. Итог: 289
искусственных входов, 578 сравнений, расхождений нет. Точные счётчики и хеши:
[`evidence/dynamic-config.json`](../evidence/dynamic-config.json).
Это не доказательство эквивалентности для любых входов или всей конфигурационной
подсистемы, но уже проверка против оригинального машинного кода, а не только
против вручную заданных ожидаемых ответов.

## Воспроизведение

Обычные проверки без исполнения образца:

```sh
make all test
make verify-text ARCHIVE=/path/to/complete/systemdc.zip
```

Только после успешного preflight в действительно изолированной среде:

```sh
make dynamic ARCHIVE=/path/to/complete/systemdc.zip \
  RE_SKILL=/path/to/re-java-native RE_CAPS=/path/to/case/AGENT_CAPS.json
```

`dynamic` вызывает `scripts/guard.py --sample` из приложенного навыка, сохраняющий
журнал. Напрямую запускать модуль `verify_config` в текущей среде нельзя.
Тесты `MachineTests` используют только авторские синтетические инструкции,
а не байты исследуемых DLL.
