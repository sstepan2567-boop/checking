# Поиск по готовому TXT1-кэшу

`recovered/native/text_table.cpp` — компилируемая реконструкция неизменяемой
таблицы, не оригинальные исходники и не декодер защищённых строк.
Конструктор получает TXT1-ресурс и отдельно уже декодированный буфер; оба
нужных набора данных копируются. `find(uint64_t)` возвращает указатель внутрь
собственного кэша либо `nullptr`. Указатель действителен, пока жив объект и
его содержимое не заменено. Неверный формат, границы, NUL-терминатор и
повторяющиеся ключи отклоняются через `std::invalid_argument`.

## Подтверждённая структура

Все RVA относятся к клиенту с базой `0x2a4416a0000`; точный SHA-256 указан
в `evidence/text-table-validation.json`. TXT1 по RVA `0x311e8a0` имеет заголовок
`<4sII>` и 60 698 дескрипторов `<QIIQ>`: ключ, смещение, длина, вспомогательное
поле. Уже декодированный буфер по RVA `0x51aa8b0` занимает `0x16d582` байт.
Вспомогательное поле не требуется для готового кэша.

Статически проверенные инструкции getter `[0x62310, 0x6245f)`:

| RVA | Инструкция / вывод |
|---|---|
| `0x62349` | `mov edx,r10d`: хеш использует младшие 32 бита ключа |
| `0x6235d` | `and edx,r8d`: маска количества слотов минус один |
| `0x62377` | `cmp qword ptr [r11+rax*8],r10`: сравнение всех 64 бит |
| `0x62381–0x62386` | увеличение слота, маскирование и линейное пробирование |
| `0x623b6`, `0x623c3` | смещение из дескриптора + база выходного кэша |
| `0x623e9–0x623eb` | состояние `2` пропускает декодирование |
| `0x62448` | возвращается вычисленный указатель |

Инициализатор `0x62460` строит индекс с числом слотов — степенью двойки,
не меньшей `max(16, 2 * count)`; здесь это **131 072**, не 65 536.
Getter использует globals: готовность `0x76f039`, счётчик активных обращений
`0x7710f8`, дескрипторы `0x771100`, слоты `0x771118/0x771120`, выходной буфер
`0x771148`, состояния `0x771160`. Это позволяет описать состояние готового
кэша, но оно не было запущено в эмуляторе из-за гейта `STATIC_ONLY`.

## Проверка и пределы

`make verify-text` читает только разрешённую по SHA-256 сборку, извлекает данные,
запускает **наш C++**, затем сравнивает смещения с Python-парсером дескрипторов.
Проверены все 60 698 настоящих ключей и столько же отсутствующих ключей с теми
же младшими 32 битами. Расхождений нет. Тексты и ключи не выводятся в отчёт.

Синтетические C++-тесты проверяют коллизии, обход конца индекса, пустую таблицу,
дубликаты, ошибки границ/формата/терминатора и независимое владение буферами.
Это подтверждает работу реконструкции на данных, **не динамическую
эквивалентность оригинальному getter**. Инициализатор оригинала также не
исполнялся. Многопоточная ленивая инициализация и преобразование через
`0x62260 → 0xf34558` не восстановлены. Реконструкция намеренно требует уже
готового NUL-терминированного кэша, а не принимает зашифрованные байты за текст.
